## PL 지시 메모

이 과제에서 가져와야 할 것은 "AI를 써 봤다"가 아니라 **AI 출력을 통제하고, 그 효과를 숫자로 확인한 기록**이다. 데모 영상보다 측정표 한 장이 더 중요하다.

- **만들 것**: 미션 문서와 과거 리뷰에서만 근거를 가져오는 코드리뷰 초안 에이전트, 그리고 그 품질을 재는 평가 하네스.
- **지금 하는 이유**: AI 활용 문항이 지원서마다 나오는데, 측정해 본 경험이 없어 매번 같은 곳에서 막힌다. 이번에 그 기준을 직접 만든다.
- **판단 기준**: 기능 수가 아니라, 처음 정한 지표가 실제로 움직였는지 본다. 지표가 안 움직였다면 그것도 결과이니 숨기지 말고 기록한다.
- **보고 방식**: 마일스톤마다 세 줄로 보고한다. 한 일, 측정한 숫자, 막힌 것.
- **금지**: 측정하지 않은 수치는 어디에도 쓰지 않는다. 평가셋을 보면서 프롬프트를 고치지 않는다.

## 배경과 문제 정의

성균관대 SCG 코드리뷰 스터디에서 대학생의 Java·Spring Boot 미션을 리뷰할 때, 리뷰 한 건에 시간이 오래 걸렸다. 지적 하나마다 미션 의도와 이전 리뷰어들의 관점에 맞춰 보는 과정을 매번 손으로 반복했기 때문이다.

- **내가 정한 좋은 리뷰**: 리뷰이가 왜 바꿔야 하는지 스스로 느끼게 하는 리뷰. 그러려면 지적마다 미션 의도와 이어진 이유가 있어야 한다.
- **시간이 든 곳**: 지적할 위치를 찾고, 그 지적이 미션 범위에 맞는지 확인하고, 범용 AI와 토론하며 문장을 다듬는 과정.
- **범용 AI의 한계**: [검토: 미션과 무관한 지적이나 근거 없는 단정이 실제로 섞였는지 — 관찰한 사례를 07 로그에 남길 것]

## 사용자와 사용 장면

사용자는 리뷰어 본인 한 명이다. 리뷰이는 에이전트를 직접 만나지 않고, 사람이 다듬어 게시한 코멘트만 받는다.

1. 미션이 바뀌면 미션 문서와 과거 리뷰를 넣어 리뷰 포인트 카드를 만들고, 직접 검수해 확정한다.
2. PR이 오면 diff와 미션 번호를 넣고 1회차 초안을 받는다.
3. 지적마다 채택·수정·폐기를 표시하고, 코멘트는 사람이 직접 게시한다.
4. 리뷰이가 응답하면 2회차, 3회차를 같은 방식으로 진행한다. 리뷰는 3회 안에 끝낸다.

## 목표와 비목표

목표는 네 가지이고, 그중 G3가 이 과제의 핵심이다. 통제 장치가 실제로 효과가 있었는지를 같은 평가셋에서 비교해 보여야 한다.

**목표**

- **G1 근거 제한**: 모든 지적에 근거 카드 ID와 실제 코드 위치가 붙고, 이를 코드로 검증한다.
- **G2 품질 측정**: 평가 전용 PR에서 사람 리뷰 대비 재현율과 채택률을 잰다.
- **G3 통제 효과 확인**: 근거 제한이 없는 v0와 근거 제한·검증기를 넣은 v1을 같은 평가셋, 같은 모델로 비교한다.
- **G4 실사용**: 실제 리뷰 [빈칸: N]건에 써 보고 회차별 소요 시간을 기록한다.

**비목표**

- PR 코멘트 자동 게시. 사람이 승인하지 않은 게시는 하지 않는다.
- 리뷰이와 직접 대화하는 봇
- 범용 코드리뷰 봇, Java 외 언어 지원
- 웹 UI, 파인튜닝, 벡터 DB. 도입할 조건은 03 설계서에 적는다.

## 왜 AI인가

코드와 미션 문서를 함께 읽고 "왜 바꿔야 하는지"를 문장으로 써 주는 선택지는 LLM뿐이다. 다만 근거를 벗어나는 출력을 막는 장치를 함께 둬야 한다.

|   |   |   |
|---|---|---|
|대안|잘하는 것|이 문제에서 부족한 것|
|정적 분석 (SonarCloud, Checkstyle)|스타일·버그 패턴 탐지|미션 의도와 연결된 이유를 설명하지 못함|
|수작업 체크리스트|일관된 기준|위치 찾기와 설명 작성이 매번 수작업 (현재 방식)|
|범용 AI 대화|설명 문장 생성|근거 범위가 없어 무관한 지적이 섞이고, 같은 결과를 다시 얻을 수 없음|
|**근거 제한 에이전트 + 검증기 (선택)**|설명은 LLM이 쓰고, 근거는 코드로 검증|근거 카드의 품질에 결과가 좌우됨|

## 성공 지표 요약

목표 수치는 P1 단계에서 베이스라인을 잰 뒤에 정한다. 측정 전에 목표부터 정하면 숫자에 맞춰 결과를 해석하게 되기 때문이다. 정의와 측정 절차는 04 평가 계획서에 있다.

|   |   |   |
|---|---|---|
|지표|정의|비교 대상|
|M1 근거 검증 통과율|검증기를 통과한 지적 ÷ 전체 지적|v0 대비 v1|
|M2 재현율|평가 PR에 사람이 남긴 지적 중 에이전트도 짚은 비율|v0 대비 v1|
|M3 채택률|(채택 + 수정) ÷ 전체 지적|v0 대비 v1|
|M4 무관 지적률|미션 범위 밖 지적 ÷ 전체 지적|v0 대비 v1|
|M5 회차별 리뷰 시간|초안 받기부터 게시까지 걸린 분|수동 리뷰 대비|
