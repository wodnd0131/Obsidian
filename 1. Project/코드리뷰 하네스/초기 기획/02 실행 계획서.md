## 단계별 작업과 완료 기준

평가셋은 P0에서 고정하고, 그 뒤로는 바꾸지 않는다. 프롬프트는 튜닝용 PR로만 확인하고, 평가셋은 버전을 확정한 뒤 한 번만 돌린다.

**P0 준비 (작업일 약 3일)**

- 01 기획서의 열린 질문 6개에 답하고 07 로그에 기록
- 리뷰이와 다른 리뷰어에게 데이터 사용 허락 받기
- 과거 PR과 리뷰 코멘트 수집, 작성자를 익명화해 JSONL로 저장
- PR을 카드용, 튜닝용, 평가용으로 나누고 나눈 기준을 기록
- 라벨 기준을 문서화한 뒤, 평가용 PR에 사람이 남긴 지적을 정답 라벨로 확정
- 에이전트 없이 수동 리뷰 [빈칸]건을 하며 회차별 시간 기록

- 게이트: 평가셋과 정답 라벨이 고정되었다.

**P1 v0와 평가 하네스 (작업일 약 5일)**

- 저장소 골격, 설정 파일, 모델명 고정
- v0: 근거 제한 없이 지적을 JSON으로 생성
- 평가 하네스: 평가셋 실행, 지적과 정답 라벨 매칭, 지표 계산, 결과 저장
- 자동 매칭 검증: 10건을 손으로 맞춰 보고 자동 결과와 비교
- v0 수치를 기록하고 목표 수치를 고정

- 게이트: v0 결과표와 목표 수치가 07 로그에 있다.

**P2 v1 통제 장치 (작업일 약 5일)**

- 근거 카드 생성기를 카드용 PR로만 돌리고, 사람이 검수해 확정
- v1 프롬프트: 카드 안에서만 근거를 고르고 카드 ID를 필수로
- 검증기: 카드 존재, 라인 범위, 인용 코드 일치 확인과 1회 재시도
- 회차 플래너
- 같은 평가셋으로 v1을 실행하고 v0와 비교표 작성
- 실패 사례를 검증기 탈락, 무관한 지적, 놓친 지적으로 분류

- 게이트: v0·v1 비교표가 있다. 개선이 없으면 원인 분석을 기록한 뒤 다음 행동을 정한다.

**P3 실사용과 정리 (작업일 약 5일)**

- 실제 리뷰 [빈칸: N]건에 v1을 쓰고 회차별 시간과 판정 기록
- 실사용 PR이 없으면 과거 PR 다시 리뷰하기로 대체하고, 그렇게 했다고 명시
- 결과 리포트: 수치와 n, 실패 사례, 한계
- 01 기획서의 이력서 사용 조건 점검
- README와 회고 작성

- 게이트: 이력서 사용 조건 5개를 모두 채웠다.

보고를 받을 때 PL이 확인하는 것은 세 가지다.

- 숫자가 04 평가 계획서의 정의대로 계산되었는가

- 비목표에 적힌 일을 하지 않았는가
