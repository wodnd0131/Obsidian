이 평가가 답할 질문은 하나다. 근거 제한과 검증기가 같은 평가셋에서 무엇을 얼마나 바꿨는가. 좋아진 것뿐 아니라 나빠진 것도 같은 표에 적는다.

## 평가 질문과 가설

가설은 세 개다. H2가 맞는지도 반드시 확인한다. 근거를 좁히면 놓치는 지적이 늘 수 있기 때문이다.

- **H1**: v1은 v0보다 근거 검증 통과율(M1)이 높고, 무관 지적률(M4)이 낮다.
- **H2**: v1의 재현율(M2)은 v0보다 크게 떨어지지 않는다. 떨어졌다면 어떤 종류의 지적을 놓쳤는지 분류한다.
- **H3**: 실사용에서 회차별 리뷰 시간(M5)이 수동 리뷰보다 짧다.

H1이 맞고 H2가 틀리면, "정확해졌지만 놓치는 것이 늘었다"가 결론이다. 그것도 그대로 보고한다.

## 데이터 분할과 접근 규칙

분할은 P0에서 한 번만 하고 고정한다. 같은 리뷰이의 PR이 여러 묶음에 나뉘지 않게, 리뷰이 단위로 나눈다. [검토: 리뷰이 수가 적으면 미션 단위로 나눌지]

|   |   |   |   |
|---|---|---|---|
|묶음|용도|열람 가능한 때|건수|
|build|근거 카드 생성|언제나|[빈칸]|
|tune|프롬프트 수정 확인|P1, P2 작업 중|[빈칸]|
|eval|최종 평가 (정답 라벨 포함)|버전을 확정한 뒤 평가 실행 때만|[빈칸: 최소 10건 권장]|

- eval 결과를 본 뒤 프롬프트를 고쳤다면, 그 버전은 v1.1로 올리고 "eval을 본 뒤 수정했다"고 기록한다.
- 데이터가 적어 3분할이 어렵다면 tune을 생략하고 build에서 확인하되, 그 사실을 결과에 적는다.

## 지표 정의와 매칭 규칙

모든 지표는 평가셋 전체에서 한 번에 계산하고, 분모와 함께 적는다. 예를 들어 "42 / 60 (70%)"처럼 쓴다.

|   |   |   |
|---|---|---|
|지표|계산|누가 판정|
|M1 근거 검증 통과율|검증기 통과 지적 수 ÷ 생성된 전체 지적 수 (재시도 전 기준과 후 기준을 따로)|검증기|
|M2 재현율|에이전트가 짚은 정답 라벨 수 ÷ 전체 정답 라벨 수|자동 후보 + 사람 확인|
|M3 채택률|(adopt + edit) ÷ 판정한 전체 지적 수|사람 (블라인드)|
|M4 무관 지적률|drop 중 irrelevant 수 ÷ 판정한 전체 지적 수|사람 (블라인드)|
|M5 회차별 리뷰 시간|회차 시작부터 코멘트 게시까지의 분|타이머|
|M6 실행 비용|PR 1건당 입력·출력 토큰, 비용, 응답 시간|실행 로그|

**정답 라벨과 지적의 매칭 (M2)**

1. 코드가 후보를 고른다. 같은 파일이고 줄 범위가 겹치거나 [빈칸: 3]줄 안에 있으면 후보다.
2. 사람이 후보마다 "같은 문제를 짚었는가"만 예·아니오로 정한다.
3. P1에서 10건을 손으로 먼저 맞춰 본 뒤 자동 후보와 비교해, 줄 허용 범위를 정한다. 정한 값은 이후 바꾸지 않는다.

## 측정 절차

판정은 블라인드로 한다. v0와 v1의 지적을 섞고 버전 표시를 가린 뒤 판정해야 내가 만든 v1을 후하게 보는 편향을 줄일 수 있다.

**평가셋 실행 (P1, P2 게이트마다)**

1. 실행 전에 모델명, 프롬프트 버전, 카드 버전, 설정값을 `runs/<날짜>-<버전>/meta.json`에 기록한다.
2. eval 묶음 전체를 v0와 v1로 각각 실행한다.
3. 평가 담당 AI가 두 버전의 지적을 섞고 버전을 가린 판정 파일을 만든다.
4. 사람이 지적마다 adopt, edit, drop과 drop 사유를 판정한다.
5. 판정을 마친 뒤에만 버전 표시를 풀고 지표를 계산한다.
6. 결과를 아래 기록표에 한 줄로 추가하고, 실패 사례 3건을 골라 07 로그에 남긴다.

**시간 측정 (M5)**

- 시작은 수동 리뷰에서는 PR을 연 순간, 에이전트 사용 시에는 초안을 연 순간이다. 끝은 코멘트를 게시한 순간이다.
- 회차마다 바로 기록한다. 나중에 기억으로 채우지 않는다.
- 같은 PR을 수동과 에이전트로 두 번 리뷰하지 않는다. 두 번째가 빨라지는 학습 효과 때문이다. 서로 다른 PR로 비교하고, 비교했다는 조건을 함께 적는다.

## 해석 규칙과 자소서에 쓸 수 있는 문장의 조건

표본이 작으므로 "이 평가셋에서 이렇게 나왔다"까지만 말한다. 일반적인 효과나 통계적 유의성은 주장하지 않는다.

- 수치는 항상 n과 조건을 함께 쓴다. 비율만 따로 떼어 쓰지 않는다.
- 비교는 같은 평가셋, 같은 모델로 돌린 결과끼리만 한다.
- 개선이 없거나 나빠진 지표도 같은 문장 안에서 함께 말한다.
- 검증기는 근거가 붙었는지만 보므로, M1을 "정확도"라고 부르지 않는다.
- 실사용 시간은 "내 리뷰 N건에서"로 한정하고, 서로 다른 PR을 비교했다고 밝힌다.

쓸 수 있는 문장의 틀은 다음과 같다. 칸은 기록표가 채워진 뒤에만 채운다.

```text
평가용 PR [n]건에서, 근거를 제한하기 전에는 지적 [a]건 중 [b]건이 미션과 무관했지만,
근거 카드와 검증기를 넣은 뒤에는 [c]건 중 [d]건으로 줄었습니다.
대신 사람이 남긴 지적을 다시 짚은 비율은 [x]%에서 [y]%로 [변화]했습니다.
```
