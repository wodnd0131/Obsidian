## union by rank
이것도 설명하긴 어렵다.

여러 집합을 하나로 합친다고 했을 때,

리스트로 구현한다고 할 때

![[../../../Repository/9주차 - Tree-19.png]]

더 작은 쪽을 큰쪽으로 옮기는게 조금이라도 더 빠르지 않을까?
-> 1에 2,3 더하기 보단, {2,3}에 1만 더하기
여기서 말한 최악의 경우 O(N^2)

-> 진짜 유의미하게 시간복잡도가 줄어들까?
=> O(N^2) -> O(NlongN)

결론적으로 최대 로그 N번 이동함을 증명
x
X+a
합치면,

2X+a

내가 속한 집합이 이동하면? 
원래크기의 2배 이상이된다. 계속 2배씩 커진다.
아무리 많이 이동해도 최대 logN번

이것과 같은 원리를 공유하는 것이 Union by Rank

find의 시간 복잡도는 트리의 깊이로 결정된다.
깊이가 4면, 가장 깊은 애를 최대한 높이는 게 목표 = 깊이를 줄이는것

> 더해지는 쪽의 최대 깊이가 늘어나지 않도록 합치기

더하는 쪽을 더 작게한다.

더해지는 쪽 = 루트가 유지되는 트리
더하는 쪽 = 루트가 바뀌는 트리

즉, 최대 높이를 유지하여 find의 시간 복잡도를 유지
![[../../../Repository/9주차 - Tree-20.png]]

이러면 log n

이때 1번 노드가 속한 연결요소의 크기를 알고싶다면
print(sz[find(1)])
