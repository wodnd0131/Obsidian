
```
import java.util.*;
class Solution {
    public int solution(String[][] clothes) {
        Map<String,Integer> map = new HashMap<>();
        
        for(String[] strs : clothes){
            map.put(strs[1],map.getOrDefault(strs[1],0)+1);
        }
        int answer =1;
        for(int count : map.values()){
            answer *=(count+1);
        }
        return answer -1;
    }
}
```
이 문제는 "카테고리별로 세는" 게 아니라 **"안 입는 선택지까지 포함해서 곱하는"** 게 핵심이라 헷갈릴 수 있어요. 차근차근 풀어볼게요.

## 왜 각 카테고리마다 count+1을 하는가

핵심 조건: **한 카테고리에서 최대 1개만 골라 입는다** (안경도 하나, 모자도 하나, 같은 종류 두 개를 동시에 착용 못 함).

그럼 "안경" 카테고리에 `{선글라스, 뿔테}` 두 개가 있다고 하면, 선택지는:

- 선글라스를 입는다
- 뿔테를 입는다
- **안경을 아예 안 쓴다**

즉 실제 옷 개수(2개)가 아니라 **선택지는 3개(2+1)**예요. 이 "+1"이 바로 "이 카테고리는 아예 스킵한다"는 선택지를 나타내는 거예요.

## 왜 곱하는가 (경우의 수의 곱셈 원리)

카테고리가 여러 개면, 각 카테고리에서의 선택은 서로 **독립적**이에요. 안경을 뭘 고르든 상의 선택에 영향을 안 주죠. 독립적인 선택들을 조합할 때 전체 경우의 수는 각 선택지 개수를 **곱하는 것**이에요.

예를 들어 안경(2개+안입음=3가지) × 상의(1개+안입음=2가지)라면:

```
(선글라스, 티셔츠) (선글라스, 안입음)
(뿔테, 티셔츠)     (뿔테, 안입음)
(안입음, 티셔츠)   (안입음, 안입음)  ← 이 조합만 문제
```

= 3 × 2 = 6가지가 나와요.

## 왜 마지막에 -1을 하는가

위 표에서 마지막 `(안입음, 안입음)` 조합 보이시죠? 이건 **"아무것도 안 입은 상태"**예요. 문제에서 "최소 한 가지는 입어야 한다"는 조건이 있으니까, 모든 카테고리에서 "안 입음"만 고른 이 딱 한 가지 경우를 전체에서 빼줘야 해요.

그래서 최종 공식이:

```
(카테고리1 선택지) × (카테고리2 선택지) × ... × (카테고리n 선택지) - 1
```

이 되는 거예요. 코드에서 `answer *= (count+1)` 하고 마지막에 `-1` 한 게 정확히 이 로직이에요.

---

**정리하면 이 문제의 사고 흐름**: "각 카테고리 안에서는 몇 가지 선택지가 있나(옷+안입음) → 카테고리끼리는 독립이니 곱한다 → 전부 안입은 경우 하나는 제외한다"

이 문제가 오늘 목표였던 "해시 활용"과 어떻게 연결되는지 보이시나요? 핵심은 카운팅(Map)이 아니라 사실 **조합론**이었고, Map은 그냥 "카테고리별로 몇 개씩 있는지" 세는 도구로 쓰인 거예요. 실전에서 자주 나오는 패턴이 이거예요 — 해시로 그룹화한 다음, 그 위에서 수학적 로직(조합, 그리디 등)을 얹는 것.
